# OneDrive for Business

File Station uses Microsoft Graph with enterprise application credentials. No Microsoft sharing links are created, and partners need no Microsoft account. DOCX editing runs in File Station's browser editor for all storage adapters.

1. Register a single-tenant application in Microsoft Entra ID. Record the **Directory (tenant) ID** and **Application (client) ID**. Under Certificates & secrets, create a client secret and record its **Value**, not its Secret ID. Arrange renewal before expiration.
2. Grant Microsoft Graph **application** permissions and tenant admin consent. Prefer `Files.SelectedOperations.Selected` with an explicit write grant on the dedicated storage folder, or `Sites.Selected` with a write grant on its dedicated SharePoint/OneDrive site. Selected scopes alone grant no access; a tenant administrator must assign the resource grant separately. Follow Microsoft's [selected-permissions guide](https://learn.microsoft.com/en-us/graph/permissions-selected-overview). Resource-scoped grants may prevent browsing ancestors or resolving a drive by user email; obtain its Drive ID and permitted Folder ID from your administrator and enter them directly.
3. For a full-access setup, open **Entra admin center → App registrations → your application → API permissions → Add a permission → Microsoft Graph → Application permissions → Sites.ReadWrite.All**, then select **Grant admin consent for your tenant**. Confirm its status says **Granted**. Microsoft currently lists `Sites.ReadWrite.All` for application-only upload sessions; it also covers the drive-list lookup. This grants read/write access across the tenant's SharePoint/OneDrive sites, not just the folder. Do not add it if tenant-wide access is unsuitable; use the selected-resource setup above instead. Delegated permissions do not authorize this connector's client-credentials flow.
4. Use a dedicated private folder or service account's OneDrive. Remove unwanted native access and inherited sharing through Microsoft administration. File Station does not change existing folder permissions. The OneDrive owner, authorized Microsoft users and tenant administrators retain their native access. A File Station folder picker cannot override that.
5. In File Station, choose **Storage → Add connector → OneDrive for Business**. Enter the tenant/client IDs and secret value. Use **Find drive** with the OneDrive owner's email, or enter a known Drive ID. **Browse folders**, open the intended folder and save. You can enter a known Folder ID directly. `root` selects the drive root for browsing; the picker shows the actual ID after opening it. Folder names such as `FileStation` are not folder IDs. If the picker cannot open a saved selection, use **Browse drive root**, then open the intended folder. New connectors and changed storage locations are checked before saving. If the folder does not exist, use **New folder name → Create folder here** in the picker; this creates a folder inside the currently selected location and selects its real ID. Existing folders are never replaced or renamed.
6. Configure capacity, retention and enabled state. The root location is locked once any file history exists; create a new connector for a different drive or folder. Editing configuration with the secret field blank preserves the existing secret.

Files have application-generated storage names and retain their display names in File Station. Application secrets and pre-authenticated upload-session URLs are encrypted at rest with the existing `CONNECTOR_ENCRYPTION_KEY`; keep that key stable. Tenant access tokens and download URLs are never sent to recipients. Deletion can leave items in Microsoft's recycle bin according to Microsoft policy; File Station's quota tracks active files, not your tenant's billed/recycle-bin usage.

Uploads use sequential **10 MiB** parts, an exact multiple of Microsoft's required 320 KiB. Existing connectors retain 8 MiB parts; the part size is persisted per file. Parts can resume after interruption. This adapter targets the global commercial Microsoft cloud; sovereign cloud endpoints need a separate configuration change.

After connecting, test a file larger than 10 MiB: pause/resume, download and compare it, then delete it. Verify the app has create/read/delete rights. Mocked integration tests validate protocol handling but cannot validate your live tenant consent or conditional access rules.

Cancelled or expired uploads are cleaned up independently. An unusable preauthenticated session URL (401/403/404/410) does not prevent checking and deleting any committed item through authenticated Microsoft Graph. Known committed item IDs skip session cancellation, and Graph deletion refreshes a rejected cached access token once. Genuine cancellation or item-deletion failures remain queued for retry. Such files stay in `deleting` and count against connector capacity, but do not block unrelated file requests or normal uploads that fit in the remaining free space. Scheduled cleanup still reports failures and retries them; a failure on one file does not prevent cleanup of other stale files. Logs include file IDs and HTTP status codes without provider URLs or credentials.

## Finding a drive and diagnosing permission errors

**Find drive** uses the application-supported `GET /users/{sign-in-address}/drives` collection and selects a uniquely identified business drive. It does not use `GET /users/{address}/drive`, whose documented permission table excludes application authentication. Discovery needs file/site application permissions covering the drive list; selected permissions can allow your known folder while denying discovery. For a scoped setup, enter the known Drive ID and Folder ID directly. Alternatively, the drive owner can sign in to [Graph Explorer](https://developer.microsoft.com/en-us/graph/graph-explorer) and run `GET https://graph.microsoft.com/v1.0/me/drive?$select=id,name,driveType`; copy its top-level `id`. This delegated lookup finds the ID without granting the storage app tenant-wide discovery permissions.

- **401:** Graph rejected the access token. Verify Microsoft Graph **application** permissions, admin consent, and matching tenant/client/secret values. The adapter refreshes a cached token once before reporting the failure; adding permissions without granting consent does not grant access.
- **403:** The authenticated app lacks access. Check consent and, for selected scopes, the explicit site/folder write grant. A selected grant may not authorize Find drive or browsing the drive root; enter the permitted folder ID directly.
- **400 invalidRequest when starting an upload:** Check **Storage root folder ID**. Microsoft requires the internal item ID belonging to the selected Drive ID; a folder name or path is not an ID. Use **Browse drive root**, open the intended folder, and save. Typing a folder name in the ID field does not create it; use **New folder name → Create folder here** in the picker instead. If the folder opens successfully but uploads still fail, check write access on that folder.
- **No drive returned:** Use the owner's Microsoft 365 sign-in address, not an email alias, and have that owner open OneDrive once to provision it. Multiple possible business drives require manually selecting the intended Drive ID.
